## Contract

`Hatifect.UI.Experience` now exposes immutable `UiStatus` with `Status`, `Empty`, `Loading`,
`Success` and `Error` kinds. `UiExperienceBuilder.Status` authors the value through the existing
`Monitor` capability, so planner placement remains the foundation `Status` presentation in the
Footer region. Existing `Monitor<T>` consumers keep their previous text scene, ID and behavior;
`Monitor<UiStatus>` also opts into the typed component.

The message remains consumer-owned content and may be supplied for the active locale. Runtime owns
the component policy:

- Empty uses `Text.Muted`, Loading uses `Text.Accent`, Success uses `Text.Success`, Error uses
  `Text.Danger`, and general Status uses `Text.Secondary`.
- `Empty`, `Loading`, `Success` and `Error` are registered domain states and can be targeted by
  typed Visual recipes.
- Error projects accessibility role `Alert`; every other kind projects `Status`. The semantic label
  is the accessible name and the message is the value.
- Status is read-only and never joins pointer or controller focus traversal.
- A kind-only change with an unchanged message invalidates rendering only. Message changes retain
  the existing measure/arrange/render path.

The public semantic surface API version stays at v1. The reviewed `UiExperienceBuilder` addition is
recorded in `Hatifect UI/PUBLIC_API_BASELINE.json`; package versions and consumer dependency direction
are unchanged.

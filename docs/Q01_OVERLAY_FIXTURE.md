## Scope

The standalone `semantic.overlay` scenario declared `requiresSave: false` in the harness manifest and `RequiresWorld: false` in the game controller. The dogfood composition root binds this overlay to the gameplay HUD layer. The existing `semantic.overlay.visual` assertion checks a visibility flag synchronously, before a render pass; it alone cannot prove that an image contains the overlay.

Both declarations now require a save/world: the canonical runner provisions its isolated working copy and the controller waits for world-ready before executing the HUD scenario. This standalone fixture also waits until the game's load fade reaches zero; it neither changes game animation state nor uses an arbitrary sleep. The existing request deadline bounds the wait, and diagnostics retain the fade alpha. This does not introduce a UI/Flow API, change persistence, lower an acceptance threshold, or claim physical input coverage. The real user saves and ordinary Mods remain outside the canonical isolated harness. Actual before/after game images verify this fixture correction; no synthetic source-mirroring test is added.

# Адаптеры и интеграции

Прочитай корневые инструкции и README затронутого адаптера. Определи поддерживаемую версию внешнего API, capability boundary, владельца lifecycle и поведение при отсутствии/несовместимости зависимости. Core и UI framework не получают зависимости на конкретный мод.

Адаптер переводит внешние данные/действия в общий контракт; semantic experience описывает представление. Не копируй доменные правила в адаптер и не меняй framework ради частного окна. Сторонний API, reflection и подписки остаются внутри адаптера. Проверяй освобождение подписок, повторное открытие/закрытие и недоступные capability.

Chests Anywhere Overlay использует точные версии UI packages из корневой package authority. `ProjectReference` на исходники UI и собственные копии UI runtime DLL в поставке CA запрещены. Новый публичный UI контракт изменяется совместно с producer и consumer в одном PR.

Команды из корня для CA: `./tools/hatifect-test ca --platform`, `./tools/hatifect-isolated-ui-ca`, `./tools/hatifect-check --platform`. Изоляция использует текущие packages и отдельный каталог установки. Обычный Mods пользователя не изменяется.

Будущий адаптер получает собственный README, зарегистрированные solution/test проекты и capability contract. Вложенный AGENTS нужен только для специфичных правил; общие остаются здесь.
